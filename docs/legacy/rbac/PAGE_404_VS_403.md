# 404 与 403 错误处理机制

## 📋 问题说明

在 RBAC 权限系统中，需要正确区分两种错误：

- **404 Not Found**: 页面不存在
- **403 Forbidden**: 页面存在但用户无权访问

### ❌ 错误的处理方式

如果直接对所有页面进行权限检查，会导致：

```
用户访问: /admin/non-existent-page

PageAccessGuard 检查权限
    ↓
用户没有这个菜单权限
    ↓
显示 403 错误 ❌ 错误！应该显示 404
```

**问题：** 页面根本不存在，却显示"无权访问"，这是不合理的。

### 正确的处理方式

先判断页面是否存在，再检查权限：

```
用户访问: /admin/non-existent-page

PageAccessGuard 检查页面是否存在
    ↓
页面不存在
    ↓
放行，让 Next.js 404 机制处理
    ↓
显示 404 错误 正确！
```

```
用户访问: /admin/rbac/users (页面存在)

PageAccessGuard 检查页面是否存在
    ↓
页面存在
    ↓
检查用户权限
    ↓
用户没有这个菜单权限
    ↓
显示 403 错误 正确！
```

## 🔧 实现方案

### 方案 1: 配置文件方式（已实现）

**优点：**
- 简单直接
- 集中管理所有页面路径
- 易于维护和查看

**缺点：**
- ⚠️ 添加新页面后需要手动更新配置
- ⚠️ 可能忘记更新导致新页面被当作 404

### 核心文件

#### 1. 页面配置文件：`config/admin-pages.js`

```javascript
// 已知存在的页面列表
export const ADMIN_PAGES = [
	'/admin',
	'/admin/rbac/users',
	'/admin/rbac/roles',
	'/admin/rbac/menus',
	'/admin/rbac/permissions',
	'/admin/finance/credits',
	'/admin/finance/packages',
	'/admin/system/settings',
	'/admin/system/usage',
	// ... 更多页面
];

// 动态路由模式（可选）
export const DYNAMIC_PAGE_PATTERNS = [
	/^\/admin\/rbac\/users\/edit\/[a-zA-Z0-9_-]+$/,
	// ... 更多动态路由
];

// 检查函数
export function isKnownPage(pathname) {
	// 1. 精确匹配
	if (ADMIN_PAGES.includes(pathname)) {
		return true;
	}

	// 2. 动态路由匹配
	for (const pattern of DYNAMIC_PAGE_PATTERNS) {
		if (pattern.test(pathname)) {
			return true;
		}
	}

	return false;
}
```

#### 2. 权限守卫：`components/admin/page-access-guard.jsx`

```javascript
import { isKnownPage } from '@/config/admin-pages';

export default function PageAccessGuard({ children }) {
	const pathname = usePathname();

	useEffect(() => {
		const checkAccess = async () => {
			// 🔍 第一步：检查页面是否存在
			const pageExists = isKnownPage(pathname);

			// 如果页面不存在，放行让 404 处理
			if (!pageExists) {
				setAccessState({
					hasAccess: true, // 放行
					pageExists: false,
				});
				return;
			}

			// 🔐 第二步：对已知页面进行权限检查
			const result = await checkPageAccessAction(pathname);
			setAccessState({
				hasAccess: result.hasAccess,
				pageExists: true,
			});
		};

		checkAccess();
	}, [pathname]);

	// 只对已知页面显示 403
	if (!accessState.hasAccess && accessState.pageExists) {
		return <Result status="403" />;
	}

	// 放行（包括 404 页面）
	return <>{children}</>;
}
```

## 🎯 工作流程

### 完整流程图

```
用户访问页面
    ↓
PageAccessGuard 激活
    ↓
检查: isKnownPage(pathname)
    ↓
    ├─ false (页面不存在)
    │   ↓
    │   放行 (hasAccess: true)
    │   ↓
    │   渲染 children
    │   ↓
    │   Next.js 路由系统检测
    │   ↓
    │   找不到页面
    │   ↓
    │   触发 app/(admin)/[...slug]/page.js
    │   ↓
    │   调用 notFound()
    │   ↓
    │   显示 404 页面 ✅
    │
    └─ true (页面存在)
        ↓
        调用 checkPageAccessAction(pathname)
        ↓
        检查用户菜单权限
        ↓
        ├─ 有权限 (hasAccess: true)
        │   ↓
        │   渲染页面内容 ✅
        │
        └─ 无权限 (hasAccess: false)
            ↓
            显示 403 错误 ✅
```

## 📝 添加新页面的步骤

### Step 1: 创建页面文件

```javascript
// app/(admin)/admin/your-module/page.js
export default function YourModulePage() {
	return <div>Your Module Content</div>;
}
```

### Step 2: 更新页面配置 ⚠️ 重要

```javascript
// config/admin-pages.js
export const ADMIN_PAGES = [
	// ... 现有页面
	'/admin/your-module', // ← 添加新页面路径
];
```

**⚠️ 如果忘记这一步：**
- 新页面会被当作不存在的页面
- 访问时会显示 404 而不是进行权限检查

### Step 3: 在后台创建菜单

```
访问: /admin/rbac/menus
创建菜单:
- 名称: Your Module
- URL: /admin/your-module  必须与页面路径一致
- 启用: 是
```

### Step 4: 分配权限

```
访问: /admin/rbac/roles
编辑角色，勾选 "Your Module" 菜单
```

## 🔍 动态路由支持

如果你有动态路由，如 `/admin/rbac/users/edit/[id]`：

```javascript
	// ... 更多动态路由
];
```

#### 方法 2: 自定义匹配逻辑

```javascript
// config/admin-pages.js
export function isKnownPage(pathname) {
	// 精确匹配
	if (ADMIN_PAGES.includes(pathname)) {
		return true;
	}

	// 动态路由模式匹配
	for (const pattern of DYNAMIC_PAGE_PATTERNS) {
		if (pattern.test(pathname)) {
			return true;
		}
	}

	// 自定义逻辑
	if (pathname.startsWith('/admin/rbac/users/edit/')) {
		return true;
	}

	return false;
}
```

## 🚨 常见问题

### Q1: 添加了新页面但显示 404

**原因：** 忘记更新 `config/admin-pages.js`

**解决：**
```javascript
// config/admin-pages.js
export const ADMIN_PAGES = [
	// ... 其他页面
	'/admin/your-new-page', // ← 添加这一行
];
```

### Q2: 动态路由总是显示 404

**原因：** 没有配置动态路由模式

**解决：**
```javascript
// config/admin-pages.js
export const DYNAMIC_PAGE_PATTERNS = [
	/^\/admin\/your-module\/[a-zA-Z0-9_-]+$/, // ← 添加模式
];
```

### Q3: 如何自动生成页面列表？

**方案：** 创建脚本扫描 `app/(admin)/admin` 目录

```javascript
// scripts/generate-admin-pages.js
const fs = require('fs');
const path = require('path');

function scanPages(dir, prefix = '/admin') {
	const pages = [];
	const items = fs.readdirSync(dir);
	
	items.forEach(item => {
		const fullPath = path.join(dir, item);
		const stat = fs.statSync(fullPath);
		
		if (stat.isDirectory() && !item.startsWith('[')) {
			const route = `${prefix}/${item}`;
			const pagePath = path.join(fullPath, 'page.js');
			
			if (fs.existsSync(pagePath)) {
				pages.push(route);
			}
			
			pages.push(...scanPages(fullPath, route));
		}
	});
	
	return pages;
}

const pages = scanPages('./app/(admin)/admin');
console.log('export const ADMIN_PAGES = [');
pages.forEach(page => console.log(`\t'${page}',`));
console.log('];');
```

运行：
```bash
node scripts/generate-admin-pages.js
```

## 📊 方案对比

### 配置文件方式（当前实现）

**优点：**
- 实现简单
- 性能好（不需要文件系统访问）
- 集中管理

**缺点：**
- ⚠️ 需要手动维护
- ⚠️ 可能遗漏新页面

**适用场景：**
- 页面数量不多
- 更新频率不高
- 团队规模小

### 文件系统扫描方式（备选）

**优点：**
- 完全自动化
- 不会遗漏页面

**缺点：**
- ⚠️ 需要在服务端运行
- ⚠️ 性能开销较大
- ⚠️ 实现复杂

**适用场景：**
- 页面数量多
- 更新频率高
- 需要完全自动化

## 🎯 最佳实践

1. **创建新页面时立即更新配置**
   ```javascript
   // 开发流程
   1. 创建 page.js
   2. 立即更新 config/admin-pages.js ← 不要忘记
   3. 创建菜单
   4. 分配权限
   ```

2. **使用代码审查确保配置更新**
   - PR 中包含新 page.js 文件时
   - 检查是否同时更新了 admin-pages.js

3. **定期检查配置完整性**
   ```bash
   # 比对实际页面和配置
   node scripts/check-admin-pages.js
   ```

4. **为动态路由创建明确的模式**
   ```javascript
   // 不推荐：太宽泛
   /^\/admin\/.*$/
   
   // 推荐：精确匹配
   /^\/admin\/rbac\/users\/edit\/[a-zA-Z0-9_-]+$/
   ```
